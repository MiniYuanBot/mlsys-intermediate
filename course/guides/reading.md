# 如何把 200 篇变成可执行的研究地图

[路线](roadmap.md)

“先读 200 篇”可能是希望你拓宽视野，也可能包含导师对阅读深度的其他预期，不能自行理解为每篇都要完整复现。可以将下面的分层记录带给导师，确认需要达到什么深度；本课程不替代他的要求。

## 三层阅读

| 层级        | 时间        | 写出什么                                                      | 什么情况下升级             |
| ----------- | ----------- | ------------------------------------------------------------- | -------------------------- |
| S：筛选     | 15–25min/篇 | 问题、关键约束、机制一句话、最关键图、排除/保留理由           | 与当前实验变量直接相关     |
| D：精读     | 2–4h/篇     | 目标函数、正确性条件、baseline、硬件/数据、主要消融、缺失证据 | 要作为最近邻或复现对象     |
| R：复现机制 | 8–20h 起    | 对应源码入口、固定 commit、一个机制复现、差异说明             | 主方向有继续价值且资源可达 |

第一轮建议 24–32 篇 S、6–8 篇 D、1–2 个 R；之后每周 6–10 篇 S、2 篇 D，逐步扩到 200 篇的主题地图。这些阅读层级存在包含关系，同一篇论文不能计数三次。若导师明确要求 200 篇精读，需要重新讨论工期和实验产出安排。

## 读一篇系统论文的顺序

1. 摘要与问题图：优化的究竟是吞吐、尾延迟、成本还是质量？约束是什么？
2. 评测章节：硬件、模型、输入/输出长度、arrival process、quality metric、baseline 版本；先判断自己能够复现到哪一层。
3. 核心机制：把状态、事件和不变量画出来；尝试写 20 行伪代码。
4. 消融和局限：若去掉组件，理论上哪项指标变化？哪张图真正检验了它？
5. 查源码：沿 benchmark 的调用栈定位关键实现，固定 commit 并记录 symbol，无需从仓库第一行开始通读。
6. 写一条反证：在什么负载/设备上作者机制可能无益？据此设计实验，不能将尚未验证的猜测写成已发现的缺陷。

## 新颖性检查

从 [资料汇总](../readings/resources.md) 选出起点，再查论文引用、作者后续工作和目标会议最新目录，扩展相关文献。以“约束 + 目标 + 方法”检索，例如 `KV mixed precision budget per head latency`，而不只搜你的新方法名称。课程核验截至 2026-10-17；开始正式课题时应再查新。

为每个研究想法建一张对照表，列出最接近的工作、相同假设、不同假设、相同机制，以及你得到的新证据。**“把两个现有模块拼起来”是实验起点，不自动构成贡献。** 有价值的贡献可以是：可靠地刻画新瓶颈，给出既有假设的反例，提出带正确性和成本分析的新策略，或在真实约束下系统性优于强基线的实现。
