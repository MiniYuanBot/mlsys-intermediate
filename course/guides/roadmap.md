# 36 小时/周路线

[选题地图](directions.md) · [总索引](../index.md) · [从 lab 到真实系统](real-systems.md)

达到 foundations 的主要能力要求后，就可以开始本路线；按实际掌握情况安排进度，已经会的内容不必为了配合日历再学一遍。**第一份可讨论的成果是可靠的复现、测量和假设，不必等到论文接收。** 课程成绩和推免排名优先，36 小时是正常周的上限，考试周减半。

本路线从 2026-10-19（周一）算作 W1，一直排到 2027 年夏季推免申请。开放阶段最容易停滞，所以 W7 以后**每周都有必交产物**：没有产物的一周，要在周报里写清卡在哪里。

## 固定周节奏

| 时间             | 任务                     | 必须留下的产物                          |
| ---------------- | ------------------------ | --------------------------------------- |
| 18h，$6\times3$h | 编码、定位错误、实现基线 | 可运行 commit、一个最小失败用例         |
| 8h，$4\times2$h  | 论文与上游源码           | 2 张精读卡 + 6–10 篇快速筛选记录        |
| 6h，$3\times2$h  | 基准测试与消融           | 一份原始记录、一张图、一句可证伪解释    |
| 3h               | 实验报告/相关工作/提案   | 更新两页研究笔记，不留到月底            |
| 1h               | 准备和进行导师讨论       | 最多 3 个有证据的问题；导师忙时先写周报 |

开始每个工作块时，写明接下来 90 分钟要修改哪个文件，或得到哪张表。每周最多推进两条假设。卡住时按下文“卡住时怎么办”的规则处理，**不要直接转去泛读资料**。

## 课时口径：先防止把任务重复计算

每个方向的完整讲义约 **5h**，包括推导、手算和指定论文/源码导读；lab 另有 **25–38h** 的必修活动（含 R 阶段和报告），按其 README 分项验收。运行几分钟参考代码不等于完成 lab：你还要实现各阶段的 TODO，独立编写反例，完成测量流程，整理数据并解释结果。可选挑战单独列出，不保证能在固定期限内完成。

九个方向合计讲义 45h、lab 277h，共 322h。主方向的一讲加实验约 30–43h，一到一周半可以完成；D3、D2 第一轮可以后补的部分见[课程索引](../index.md)的工作量表。不需要做完九个实验。

这些是面向已完成 foundations 的**计划工时，尚无学生试学数据**。允许约 $\pm 25\%$ 的个人差异；调试超时如实计入，不要靠删去负结果来满足计划。完成第一个方向后，用真实用时校准后面的安排：

| 活动        | 开始前的承诺             | 结束时的记录                           |
| ----------- | ------------------------ | -------------------------------------- |
| 推导/读代码 | 本次要回答的两道问题     | 自己的手算、调用链或疑问，不是论文摘要 |
| 实现/调试   | 函数、边界输入、预期结果 | commit、失败用例、修复原因与实际小时   |
| 测量        | 矩阵、baseline、计时范围 | 所有成功/失败配置及原始记录            |
| 分析/写作   | 一张图要检验什么         | 图、结论、不能推出的结论与下一次实验   |

讲义 5h 里已经导读过的论文，不再计入 lab；lab 的论文活动用于**对照自己的测量、写机制差异和研究问题**。GPU 运行时间与人的投入时间分开记，等机器跑一夜不能算八小时学习。

## 第 1–2 周：72 小时有限扫描

**扫描不是读完九讲，也不是完成九个 Part A。** 每个方向 3h 选择性导读加 2h 最小任务，目的是找到你愿意继续追问的问题。每天 6h，每周 6 天。

| W2-D3 | D9 导读 3h；最小任务 2h；整理 1h                                   | Qwen3-1.7B 单层 FLOPs/字节手算表；3 卡 4 层例子的 max-flow 与 min-cut         |
| W2-D4 | 九方向打分 2h；两项最近邻筛读 2h；读苗老师主页与 FAQ 1h；定选择 1h | 打分表；主方向一个、备选一个；FAQ 要求的联系材料清单                          |

导读每次只选该讲的问题定义、关键推导、手算和前沿方法比较，不要求同时完成全部自测和上游源码练习。最小任务可以用草稿或小脚本，但不能算 lab 验收。PyTorch 不熟时，在 W1-D3 之前用缓冲时间做 [PyTorch 桥接](pytorch-bridge.md)的前两项。

这 72h 已经包含编码、阅读、测量和整理，**不要再叠加“固定周节奏”的 36h**。固定节奏从 W3 起使用。某项超时先用缓冲；仍超时就把主方向 lab 顺延，保留九方向的打分记录，减少旁支任务。

联系导师的要点（据[主页](https://hsword.github.io/)和 [FAQ](https://hsword.github.io/faq/)，2026-10-18 核验）：先读 FAQ，再把 CV 和成绩单发到 xupeng.miao@pku.edu.cn；FAQ 说明邮件多、不保证回复，对本科生的表述是可以发 CV、有合适项目时参与；两周没有回复可以提醒一次。FAQ 没有规定邮件标题格式。一页摘要以 lab 的实测数字为主，少写泛泛的兴趣表态。提醒之后仍无回复，不反复催，照计划推进，W10 有了提案 v2 再发一次进展更新。

**转向规则**：两周仍没有可运行 baseline，就把模型/数据规模降一档；结果只对一个手工构造的输入成立，就回到工作负载真实性；最接近的论文已经研究了同一机制与目标，就转为复现工作或组内子问题，不要换个名字继续原选题。

## 卡住时怎么办

按时间盒执行，到点就切换：

1. **45 分钟**：同一个错误没有进展，先缩小输入、核对一个 oracle 或已知正确的参考实现。
2. **90 分钟**：仍无法定位，写下 5 行复现步骤（输入、命令、预期、实际、已排除的原因），切换到本周表格里的另一项任务。
3. **1 个工作日**：同一个问题耗满一天，把复现步骤发给组内同学或写进周报，向导师提问；同时换一个 TODO 继续。
4. **1 周**：本周必交产物没有完成，下周不新增任务，先补完；在周报第一行写“未完成”和原因。
5. **2 周**：仍没有可运行 baseline，把模型或数据规模降一档（例如 1.7B 换 0.6B、完整 trace 换前 4k 个请求）。
6. **3 周**：主假设没有任何信号，按下面的负结果框架改写问题，不再追加策略复杂度。

**什么时候必须找导师**（不用等周会）：准备花超过一周做新方向之前；结果与最近邻论文明显矛盾；需要服务器、数据或组内代码；发现自己的题目可能与组内在做的课题重叠。

**负结果的写法**：负结果也是可以投稿的贡献，前提是条件写清、测量可信。框架是“在条件 $X$ 下，方法 $Y$ 不比基线 $Z$ 好，原因是 $W$，并给出 $Y$ 会有用的反事实条件”。本课程已经有几个现成的例子：D4 平稳 trace 上自适应推测不如最好的固定 $k$；D3 模型推算的 DP 优势在真实回放里消失；D7 单 copy engine 下单槽 overlap 为 0。负结果论文同样需要强 baseline、多负载和可重跑 artifact。
