# 36 小时/周路线

[选题地图](directions.md) · [总索引](../index.md)

达到 foundations 的主要能力要求后，就可以开始本路线；按实际掌握情况安排进度，无需为配合日历重复学习已掌握的内容。**第一份可讨论的成果是可靠的复现、测量和假设，不必等到论文接收。** 保持课程成绩和推免排名的优先级，36 小时是正常周上限；考试周可减半。

## 固定周节奏

| 时间             | 任务                     | 必须留下的产物                          |
| ---------------- | ------------------------ | --------------------------------------- |
| 18h，$6\times3$h | 编码、定位错误、实现基线 | 可运行 commit、一个最小失败用例         |
| 8h，$4\times2$h  | 论文与上游源码           | 2 张精读卡 + 6–10 篇快速筛选记录        |
| 6h，$3\times2$h  | 基准测试与消融           | 一份原始记录、一张图、一句可证伪解释    |
| 3h               | 实验报告/相关工作/提案   | 更新两页研究笔记，不留到月底            |
| 1h               | 准备和进行导师讨论       | 最多 3 个有证据的问题；导师忙时先写周报 |

开始每个工作块时，写明接下来 90 分钟要修改哪个文件，或得到哪张表。卡住 45 分钟后，先缩小输入、核对一个 oracle；仍无法定位时，写下 5 行复现步骤。**遇到问题时，不要直接转去泛读资料。** 每周最多推进两条假设。

## 课时口径：先防止把任务重复计算

每个方向的完整讲义约 **5h**，包括自足推导、手算、指定论文/源码导读；lab 另有 **23–26h** 的必修活动，按其 README 分项验收。运行几分钟参考代码，并不等于完成 lab。你还需要实现三个阶段的 TODO，独立编写反例，完成测量流程，整理数据并解释结果。开放研究挑战单独列出，不保证能在固定期限内完成。

全部八方向合计课程40h+实验200h=240h。主方向的一讲加实验约28–31h，可以放在一个36h周内，其余时间用于最近邻论文更新和导师讨论；不需要连续做完八个实验。

这些是面向已完成 foundations 的**计划工时，尚无学生试学用时数据**。允许约 ±25% 的个人差异；调试超时应如实计入实际工时，不能靠删去负结果来满足计划。首次完成一个方向后，用真实时间校准后续安排：

| 活动        | 开始前的承诺             | 结束时的记录                             |
| ----------- | ------------------------ | ---------------------------------------- |
| 推导/读代码 | 本次要回答的两道问题     | 自己的手算、调用链或疑问，非复制论文摘要 |
| 实现/调试   | 函数、边界输入、预期结果 | commit、失败用例、修复原因与实际小时     |
| 测量        | 矩阵、baseline、计时范围 | 所有成功/失败配置及原始记录              |
| 分析/写作   | 一张图要检验什么         | 图、结论、不能推出的结论与下一次实验     |

如果已在讲义的 5h 中完成某篇论文的导读，就不再将同一活动计入 lab；lab 的论文活动用于**对照自己的测量、写机制差异和研究问题**。实际 GPU 运行时间与人的投入时间分列，不能把等待机器训练一夜算成八小时学习。

## 第 1–2 周：72 小时有限扫描

**扫描不是完整读完八讲，也不是完成八个 Part A。** 每个方向给 3h 的选择性导读和 2h 的最小任务。第一轮用于找到你愿意继续追问的问题，不要求在两周内完成八个完整 lab。每天总计 6h，每周 6 天。

| 日程  | 当日 6h 的精确分配                               | 最低产物/停止点                                          |
| ----- | ------------------------------------------------ | -------------------------------------------------------- |
| W1-D1 | 环境 1h；PyTorch 桥接选做 2h；D1 导读 3h         | 环境记录；KV 字节账与两种分组的手算；不开始完整量化器    |
| W1-D2 | D1 最小任务 2h；D2 导读 3h；整理 1h              | 量化一个常量/尾组并核对；画 int4 字节与 warp lane 映射   |
| W1-D3 | D2 最小任务 2h；D3 导读 3h；整理 1h              | 单个 byte 解包真值表；算专用 kernel 的盈亏平衡，不追性能 |
| W1-D4 | D3 最小任务 2h；D4 导读 3h；整理 1h              | 对三种形状穷举两个 bucket 的成本；手算接受长度期望       |
| W1-D5 | D4 最小任务 2h；D5 导读 3h；整理 1h              | 两个 k 候选的约束比较；画共享前缀 pin/evict 状态         |
| W1-D6 | D5 最小任务 2h；D6 导读 3h；整理 1h              | 一条容量不足的事务回滚手算；LoRA 参数与梯度推导          |
| W2-D1 | D6 最小任务 2h；D7 导读 3h；整理 1h              | 观察 $B=0$ 首步梯度；手算 dispatch offsets 与专家字节账  |
| W2-D2 | D7 最小任务 2h；D8 导读 3h；整理 1h              | 两个 token 的重复路由/加权合并；手工排三条长短任务       |
| W2-D3 | D8 最小任务 2h；八方向评分 2h；两项最近邻筛读 2h | 构造分段 gap 或缺组反例；选一个主方向和一个备选          |
| W2-D4 | 主方向余下讲义 2h；其 lab 实现 4h                | 补齐完整讲义；按 lab README 完成一个核心接口及测试       |
| W2-D5 | 主方向实现/调试 3h；测量 2h；整理 1h             | 小规模正确性结果；至少一张有原始数据的表，失败也记录     |
| W2-D6 | 证据复查 2h；初始提案 2h；讨论准备 1h；缓冲 1h   | 两页问题说明：现象、已有方法、未知项、下周唯一实验       |

导读每次只选该讲的问题定义、关键推导、手算和前沿方法比较；不要求同时完成全部自测和上游源码练习。最小任务可用草稿或小脚本完成，但不能算作 lab 验收通过。如果主方向扫描尚未覆盖完整讲义，就用 W2-D4 的 2h 补齐；仍未完成的部分移至 W3，不压缩正确性验证时间。

这份表的 72h 已包含编码、阅读、测量和整理，因此**不要再叠加上方“固定周节奏”的 36h**。固定节奏用于 W3 起的正常研究周。某任务超时先使用缓冲；仍超时则把主方向完整实验顺延，保留八方向的选择记录，减少旁支代码任务。

## 第 3–6 周：把一个方向做深

- **W3**：按主方向 lab 的实际剩余时间完成基础实现、独立反例与 baseline；避免重做两周扫描已经完成的任务。交付边界测试、原始表和函数调用链。
- **W4**：主方向C阶段完整实现、已有测量与补充消融；用 held-out workload 检查现象是否稳定。交付“哪些结论与论文一致，哪些不能比较”，并核对最近邻是否已解决同一问题。
- **W5**：接入真实模型/真实 trace；按训练/测试工作负载分离调参。交付第二种工作负载上的结果与失败案例。
- **W6**：重跑、统计区间、最近邻更新。交付 [两页提案](../templates/proposal.md)，请导师决定继续、收窄、转向或加入组内项目。

**转向规则**：两周仍没有可运行 baseline → 把模型/数据规模降一档；结果只对一个手工构造输入有效 → 回到工作负载真实性；最接近的论文已研究同一机制与目标 → 转为复现工作或组内子问题，不能仅换个名称继续原选题。

## 到 2027 年夏季的阶段目标

以下是个人规划，不是学校或会议的官方截止日期。当前日期为 2026-10-17；若 foundations 尚需时间，将前两阶段顺延，并与导师协商范围。

| 时间窗口           | 你能控制的交付                                      | 决策                                      |
| ------------------ | --------------------------------------------------- | ----------------------------------------- |
| 2026-10 至 11      | 完成扫描，1 个可靠 baseline，周报节奏               | 主选一项、备选一项                        |
| 2026-12            | 可证伪提案，初步真实 workload，明确个人贡献         | 是否申请服务器/加入现有课题               |
| 2027-01 至 03      | 核心机制、强基线、质量约束、多 workload             | 是否有值得写的发现；无则尽早转向          |
| 2027-04 至 05      | 消融、规模验证、失败边界、可重跑 artifact、论文初稿 | 与导师决定投稿渠道和署名贡献              |
| 2027-06 至夏季申请 | 项目说明、代码、报告/预印本或在投状态、推荐沟通材料 | 如实说明“已录用/在投/初稿/复现”，分别准备 |

正式推免资格依赖本校规则与排名，导师接收依赖招生安排，论文录用依赖评审；都不能由“完成一个仓库”保证。已有指导机会时，尽早展示能评估的工作，有助于获得具体反馈，不必一直等待一个完美的新点子。
