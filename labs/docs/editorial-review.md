## 审核标准

每个阶段都有实质算法填空；每个TODO有输入/输出或不变量提示；学生和参考文件标记配对；测试不随solutions覆盖；前沿机制进入可运行路径；计时范围和CPU/GPU证据明确；评分映射已有可执行检查和人工报告；工时包含自己写代码、调试、独立反例与分析。

[代码量报告](workload.md)统计123个TODO、2038行参考有效实现，八个实验各211–284行。三个阶段的代码不依靠文字中的“学生以后自行补充完整系统”来凑工作量。完整课程40h，实验200h，计划共240h；暂无学生试学工时样本。

## 审核实际发现并修复的问题

| 位置             | 发现                                                          | 修复和验证                                                                  |
| ---------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Lab1 INT4        | 有限±FLT_MAX的float差值溢出，subnormal scale可能变0           | double量化算术、最小正scale、解码有限饱和；极值和subnormal回归通过          |
| Lab6 adapter加载 | 原输入finite，但转换目标dtype后可溢出；逐项写会破坏事务       | 先转换并检查全部目标tensor，再统一copy；最后一项失败且前项不变的回归通过    |
| Lab4控制         | 无观测的保守下界为0，策略会永远选k0；开放回放不能证明在线恢复 | 明确`conservative_no_probe`为负基线；验证其时间线与k0相同，标明B为open-loop |
| Lab5身份         | 同样后块token出现在不同祖先下，容易被错误复用                 | 新增两个祖先根都驻留时仅能命中各自合法前缀的反例                            |
| Lab7数值验收     | max-error比较可能忽略NaN                                      | 显式finite检查，再比较CPU oracle                                            |

| Lab8指标         | 每wave行混用最终累计计数                                      | 改为当前wave的实际快照；补2worker时序与版本/组拒绝反例                      |
| Lab3编译         | 不同策略共用Dynamo guard导致累积超出recompile_limit           | 每策略重置Dynamo状态，保留磁盘cache并标明非冷编译                           |
| Lab3日志         | Python缓冲与native子进程交错，破坏JSONL                       | 启动子进程前flush，runner传递unbuffered环境，重跑并成功导出                 |
| 共用CSV导出      | 相邻JSON记录字段不同，DictWriter按第一行列集合失败            | 对列取有序并集；所有正式bench表实际导出核验                                 |

## 公开资料如何进入实验

每个lab新增`resources.md`，列出原项目的具体文件/函数、借鉴机制、对应TODO与简化边界。来源包括KIVI/PQCache/FAISS、AWQ/Marlin、PyTorch Inductor和hooks、AdaServe、SGLang/vLLM/CacheBench、MoE-Infinity/MegaBlocks、verl/DARTS及CS336课程。链接可达和源码阅读不等于完成上游系统复现。

课程讲义同步更正旧版“没有实现PQ”“只有传输循环”“规划用手工常数”等描述。内容目录为`course/`、`labs/`、`solutions/`。后续按用户澄清补齐根目录README、Git规则、格式配置以及`.vscode/`、`.obsidian/`共享设置；格式参数与工具版本仍沿用foundations，详见[格式说明](formatting.md)。

## 保留的限制

本次验证机器为WSL/Linux上的RTX4060 Laptop 8GB，CPU路径和CUDA路径分开记录。未实机验证Mac、原生Windows、多GPU和HPC平台。实验使用缩小的模型/数值问题/事件负载，不能由通过验收推断真实LLM性能、论文新颖性或一作成果已经达成。研究扩展需真实工作负载、强基线和导师反馈。

本次没有修改实验算法、测试或评分权重。已有硬件运行记录保留原样，不能将新增图解或手算当作新的 GPU 性能测量。
