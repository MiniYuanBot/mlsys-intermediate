## 修订前后与 foundations

foundations 没有统一成对标记，因此另用相同规范化规则比较同名学生/参考文件，累计 diff 中新增/替换的参考有效行。该方法与上表在新版恰好给出相同总量，但一般并不保证；不能直接把文件总行数当作待实现量。原始比较见 [baseline-comparison.json](evidence/revision3/baseline-comparison.json)。

| 项目                       | 各实验的新增/替换参考有效行            | 合计 |
| -------------------------- | -------------------------------------- | ---: |
| foundations lab0–7         | 255, 143, 149, 327, 301, 110, 73, 25   | 1383 |
| 修订前 intermediate lab1–8 | 47, 14, 44, 29, 60, 22, 44, 54         |  314 |
| 本次 intermediate lab1–8   | 211, 252, 264, 259, 256, 259, 253, 284 | 2038 |

新版每实验211–284行实质填空，原版仅14–60行。foundations各实验承担的目标不同，不能把行数理解成其质量排名；这里的对照只是证明工作量确实进入学生需要实现的算法。

## 工时如何对应任务

A用5–6h完成格式、统计、索引和数值基础；B用7–8h完成DP、状态机、并发/缓存或CUDA核心；C用8–10h完成论文启发机制、接线、独立oracle与实测；报告3–4h。具体阶段预算以每lab任务书为准。读讲义40h与实验200h分列，总计240h；按36h/周约6.7周，但推荐只深入一个主方向。

这些是设计估时，没有学生试学样本。记录每次实现/调试的实际小时、卡点与最小失败输入，用第一项完整实验校准后面的安排。编译或跑参考程序数秒/数分钟不能折算成自己的学习时间。

## 复查命令

```bash
python tools/workload_audit.py --output results/workload.json
python tools/run.py --lab 1 --impl student --mode test --part A
python tools/run.py --lab 1 --impl reference --mode test --part A
```

命令 cwd 为 `labs/`。配对缺失、编号重复、阶段空缺、参考仍含未实现桩会让审计失败。它不能自动证明注释充分、算法正确或实验有研究价值，因而还需要[交叉审核](editorial-review.md)与[实际试跑](validation.md)。
